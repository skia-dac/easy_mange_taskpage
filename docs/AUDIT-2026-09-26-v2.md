### Mineurs (ouverts)

- `useAgendaData.ts:41` écoute `app_settings` en entier : un changement d'accent ou de taille de texte relance les 17 requêtes. Écouter `app_settings:week_start`, `app_settings:rotation_anchor`, `app_settings:spaces` (le mécanisme existe).
- `useSharedLiveQuery` : l'abonné racine (notifications) garde l'agenda vivant en permanence, donc `today` n'est recalculé qu'à la première écriture après minuit. Recharger aussi au retour de l'app ou au changement de jour.
- `engine.ts:319` : curseur de réception `= server_updated_at` du dernier + `gt` : si une page de 500 lignes se termine sur un même horodatage, les suivantes de ce même horodatage sont sautées. `gte` + déduplication.
- Toast : un second message remplace le premier sans transition et perd son « Annuler » ; masqué par le clavier si un message survient pendant une saisie.
- `FormScreen` : mesure sans attendre le rendu (un champ monté au même rendu peut donner `y = 0`) ; `FieldShell` défile sur tout changement d'`error`, pas seulement après un envoi (sans symptôme aujourd'hui, tous les formulaires passent par `useSave`).
- `KeyboardAvoiding.tsx:13` : décalage iOS fixe à 100, faux sous modale ou en grand texte (`useHeaderHeight()`).
- Onboarding : échec d'enregistrement des espaces seulement journalisé ; la carte d'espace porte le libellé mais le rôle `checkbox` est sur un `View` interne (VoiceOver lit « bouton » sans état).
- `useSave` : après une erreur non liée à un champ, les anciennes erreurs de champ restent affichées jusqu'au prochain succès.
- `userMessage` accepte tout message préfixé `money.` / `auth.` : une clé d'écran passerait ; préférer des préfixes stricts.
- `currency: z.string().min(3).max(3)` sans clé sur objectif / charge / opération : erreur muette si les réglages sont corrompus.
- ~35 champs texte avec `error=` mais sans `maxLength` (erreur visible seulement après coup) ; `HabitDaySheet` raison sans schéma.
- `settings.scheduled` : paire `_one/_other` sans appel (clé morte).
- `loadErrors.ts` : la couche `db` importe un dialogue de l'UI (pas de cycle, mais dépendance inversée).

## 4. Points forts confirmés (à préserver)

1. Écritures transactionnelles + outbox, `softDelete` universel, conflits conservés, schéma serveur généré et vérifié sur Postgres en CI, réponses serveur désormais vérifiées par zod.
2. Sécurité : aucun secret dans l'app, RLS sur 27 tables + `sync_mutations` + bucket par utilisateur, `mysky_push` en `security invoker`, SQL paramétré, verrou fail-closed, aucune donnée personnelle dans les logs.
3. Local-first : une seule lecture partagée par donnée, réglages notifiés par clé, cache conservé entre écrans.
4. UI : kit cohérent, couleurs par tokens, sombre partout, toasts avec annulation, chargements et états vides cohérents, retours de navigation sûrs.
5. i18n : vrais pluriels, unités traduites, parité FR/EN et clés utilisées testées.
6. Tests : 354, ciblés sur les cascades, la synchro (données et fichiers), le cache partagé, les conflits.

## 5. Suites de l'audit 2 (faites, commit `141d139`)

- « Annuler » après Terminer restaure l'état d'avant (« en cours » compris).
- Réception d'une suppression : jamais d'effacement d'un chemin qui remonte.
- Ajouter une opération : le pavé se retire quand le clavier est ouvert sur la note.
- Toast : placé au-dessus de la barre d'onglets seulement sur les onglets ; annoncé à VoiceOver / TalkBack.
